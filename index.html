About me

I use AI to program faster, not to think for me. I decide what gets built and how it fits together, and every change is checked with unit tests and real in-game testing before it ships.

  • I make the callsAI drafts and I edit. Architecture, trade-offs and what's worth building stay with me, and nothing merges without my review.
  • Skills over defaultsDefault AI output is generic. I give it skills: written rules for how I work, like my Java conventions, project structure, testing and commit style. Each project keeps a short knowledge base of decisions and verified fixes, so the same mistakes don't come back.
  • Research, decide, buildBigger tasks go in steps. First it reads the codebase and docs, then it weighs the options, then it writes the code, and I check the result at each step. The code ends up reading like code I'd write myself.

I've been a software developer specializing in Minecraft plugins since 2019, and not once have I had to use NMS, the server's internal code that changes with every update.

  • API firstI always go through the server API. It stays stable between versions, so code written against it keeps working.
  • Libraries for the restWhen I need protocol-level work, libraries like PacketEvents wrap the NMS and packet code for me and handle the version changes.
  • Built to lastMy plugins can go unmaintained for years and still work on the latest versions. Punishments hasn't been updated in years and still runs on 26.3.
